# RustCache Client — OS/DE, обработчики прокси, TUN MVP, кнопка «Тест»

Итерация поверх уже реализованного `crates/rustcache-client` (local proxy `127.0.0.1:31280` → RustCache `:3128`/`:3129`, fail-open DIRECT, dirty-протокол `proxy-restore.json`). Scope: **только клиент**; сервер не меняем. Подписи GUI — русские.

## Требования (подтверждено)

1. На старте определять **ОС + DE**; если платформа не поддерживается — понятное сообщение (CLI + GUI).
2. Отдельные обработчики system-proxy: **Debian/Ubuntu KDE**, **GNOME**, **Windows**, **macOS**.
3. **TUN TCP-only MVP** (80/443 → local proxy, прочий TCP → raw DIRECT, UDP/DNS — мимо TUN через host-routes).
4. Кнопка/CLI **«Тест»**: GET `http://example.com/` (a) через system proxy, (b) forced через `127.0.0.1:31280`; проверка маркера клиента + `X-RustCache-*`. Fallback на локальный origin-fixture.

Решения по умолчанию: маркер `X-RustCache-Client: 1`; feature `tun` **default off**; KDE restore — ровно snapshot (отсутствующий ключ → `--delete`); system-leg теста обязателен только при capture on.

## Целевая платформа

| Поддержка | System proxy | TUN |
|---|---|---|
| Windows | да (HKCU WinINET) | да (wintun, admin) |
| macOS | да (`networksetup`) | best-effort utun (root) |
| Linux GNOME | да (`gsettings`) | да (`/dev/net/tun`, CAP_NET_ADMIN) |
| Linux KDE Plasma | **да (`kioslaverc`)** | да |
| Linux другой DE / иная ОС | **нет** — сообщение + hint `--mode off` | нет |

Fail-open local proxy (`ProxyServer`) работает **везде** — unsupported DE только блокирует `sysproxy::enable` / `mode=system|tun`, не `mode=off`.

## 2. Детект OS/DE (`platform.rs`)

1. OS: `cfg!(target_os=…)` → `Windows | Macos | Linux | Unsupported`.
2. Linux DE (приоритет): `XDG_CURRENT_DESKTOP` split по `:`, case-insensitive (`gnome`→Gnome, `kde`/`plasma`→Kde); fallback `DESKTOP_SESSION`, `XDG_SESSION_DESKTOP`; затем tool-presence (`kwriteconfig6|5` → Kde; `gsettings` → Gnome) — **только** fallback.
3. `sysproxy_supported`: Win/macOS true; Linux + Gnome|Kde true; иначе false + reason.
4. `tun_supported`: Win/macOS/Linux true (иная ОС — false).

Тест: `detect_with_env` matrix (`ubuntu:GNOME`, `KDE`, `sway`, empty).

**Сообщение unsupported** (CLI `proxy on` / `run --mode system` → exit **5**):

```
unsupported platform/desktop: linux/xfce
  supported: Windows, macOS, Linux GNOME, Linux KDE Plasma
  hint: run with --mode off and set http_proxy/https_proxy=127.0.0.1:31280
```

GUI: «Платформа не поддерживается: … Нужен Windows, macOS, GNOME или KDE. Локальный прокси: режим Off.» `proxy status` (read-only) → `sysproxy: unsupported (linux/xfce)`, exit 0. `doctor` — строка + hint. `run --mode off` — всегда работает.

## 3. KDE handler (`sysproxy/linux/kde.rs`)

Файл `$XDG_CONFIG_HOME/kioslaverc`, группа `[Proxy Settings]`. Инструменты: `kwriteconfig6`/`kreadconfig6`, fallback `*5`. Формат: `httpProxy`/`httpsProxy` = **`"{host} {port}"`** (пробел), `NoProxyFor` = comma-list, `ProxyType=1` (manual).

**snapshot:** `ProxyType`, `httpProxy`, `httpsProxy`, `ftpProxy`, `socksProxy`, `NoProxyFor` (null если ключа нет) + envelope `"handler":"kde"`.

**apply:** httpProxy + httpsProxy → `{host} {port}`; `NoProxyFor` = `localhost,127.0.0.1,::1,*.local` + bypass (comma); `ProxyType 1`; `notify_kde()` (best-effort); msg: **`kde manual proxy {host}:{port}`** (обязательный wording — не «gnome»).

**restore:** ровно snapshot; отсутствующий ключ → `--delete`; `notify_kde()`; msg `kde proxy restored`.

**notify_kde()** (ошибки глотаем):
`dbus-send --type=signal --session /KIO/Scheduler org.kde.KIO.Scheduler.reparseSlaveConfiguration string:""` (+ fallback qdbus). Fallback без kwriteconfig — прямая запись INI (`write_kioslaverc_direct`).

**dry_run** — точные строки kwriteconfig + dbus-send (снапшот-тесты). **current_proxy:** parse `"host port"` если `ProxyType==1`.

**Restore по envelope:** `disable`/`recover_if_dirty` вызывают handler из `"handler"` в snapshot (не текущий detect — DE мог смениться); неизвестный id → fallback `platform::detect()`.

Обёртка `windows.rs`/`macos.rs` в `*Handler` — тела функций не менять, добавить `current_proxy()`.

## 4. Маркер клиента + тест

### Маркер

| | |
|---|---|
| Имя/значение | `X-RustCache-Client: 1` |
| Inject | `rewrite_for_origin` (direct) **и** `http_via_connected` (upstream — иначе путь к rustcache теряет маркер) |
| Spoof | strip входящих `X-RustCache-Client` (case-insensitive) → всегда свой `1` |
| CONNECT/HTTPS | **не** инжектируем (payload шифрован); limitation в doctor/test output |
| Проверка в тесте | forced: marker **есть**; direct: **нет**; плюс `X-RustCache-Status`/`-Version` от rustcache (если up) |

Константы + `inject_client_marker` / strip в `http_parse.rs`; unit-тесты (spoof → `1`, rewrite содержит маркер).

### `connectivity.rs` + CLI `test`

```
rustcache-client test [--url URL] [--timeout-secs N] [--https] [--no-fallback]
```

`TestReport { url, legs: Vec<LegResult>, used_fixture, passed, lines }`, `LegKind::{Direct,Forced,System}`.
Мини HTTP/1.1 клиент на tokio (без reqwest).

| Leg | Как | Pass |
|---|---|---|
| Direct | TCP origin, origin-form | 2xx/3xx; marker=нет; X-RustCache-* = нет |
| Forced | через `cfg.listen` (absolute-URI) | 2xx/3xx; marker=есть; `X-RustCache-Status` желательна (без rustcache — ok с note fail-open) |
| System | через `current_http_proxy()` | если capture on → marker=есть; иначе informational |

Fallback: timeout/refused → local fixture `127.0.0.1:0` (echo headers); pass = forced marker=yes, direct marker=no (bypass `127.0.0.1` уводит в Direct — маркер всё равно инжектится в ProxyServer).

Вывод CLI:

```
url: http://example.com/
direct: 200 marker=no  x-rustcache=—      OK
forced:  200 marker=yes x-rustcache=MISS  OK
system:  200 marker=yes x-rustcache=HIT   OK
overall: OK
```

Exit: 0 pass · 1 fail · 4 all unreachable · 5 platform.

### GUI

Секция «Диагностика»: кнопка **«Проверить соединение»** → `rt.spawn(connectivity::run…)` → pane («Прямое / Через прокси клиента / Системный прокси» + маркер + X-RustCache-Status). Работает и при capture=off (system = пропущен).

## 5. TUN TCP-only MVP (feature `tun`)

Deps optional: `tun` (async), `smoltcp` (ipv4+tcp+ip), `nix` (routes). Windows: `wintun.dll` рядом с exe (в release zip). Elevation: Linux `CAP_NET_ADMIN`/root, macOS root, Windows admin. Errors Permission → exit **3**.

```
пакеты → tun AsyncDevice → smoltcp (addr 198.18.0.1/15)
  TCP :80  → HTTP-proxy handshake к 127.0.0.1:31280 (absolute-form)
  TCP :443 → CONNECT dest к 127.0.0.1:31280
  TCP иное → raw splice DIRECT (fail-open)
  UDP → drop
```

Hand-off: tun-flow **эмулирует клиента** ProxyServer (не дёргает внутренние handle_*). Proxy down → flow DIRECT.

Routes: `0.0.0.0/1` + `128.0.0.0/1` dev tun0. **DNS safety (обязательно):** `preserve_dns_routes()` — host-route `x.x.x.x/32` к DNS через **старый** default gateway, иначе resolve умирает. Dirty snapshot: `{iface, addr, routes, dns_routes, old_default}` → recover удаляет routes + iface. `Capture::disable`: сначала tun, потом sysproxy. Fallback `fail_open`: TUN fail → system proxy → mode off + warn.

CLI/GUI: `--mode tun` при `--features tun`; без feature → «TUN is not compiled in», exit 5. Label «TUN» вместо «TUN (soon)».

## 7. Verification (manual)

**KDE (машина пользователя):** `make build-client && make stop-client && make start-client CLIENT_MODE=system` → status `kde manual proxy 127.0.0.1:31280`; `kreadconfig6 --file kioslaverc --group 'Proxy Settings' --key ProxyType` → `1`, `httpProxy` → `127.0.0.1 31280`; GUI-тест / `rustcache-client test` → forced marker=yes + X-RustCache-Status; `stop-client` → ProxyType восстановлен; `kill -9` → dirty recovery на старте.

**GNOME:** regression `gsettings get org.gnome.system.proxy mode`. **Win/macOS:** `reg query` / `networksetup -getwebproxy` + kill-recover.

**TUN linux:** `setcap cap_net_admin,cap_net_raw=eip target/release/rustcache-client`; `run --mode tun`; `curl http://example.com/` **без** env → HIT в `/api/requests`; `dig` работает; Ctrl-C → routes/iface удалены.

## 8. Risks (главное)

- **DNS через TUN** без host-routes → чёрная дыра resolve (главный footgun) → `preserve_dns_routes()` обязателен.
- TUN + VPN: конфликт routes `0.0.0.0/1` — документировать.
- KDE Plasma 5/6 dbus-имена — notify best-effort; apply пишет kioslaverc в любом случае.
- HTTPS marker невидим без MITM — note + optional `--https` leg.
- `wintun.dll` distribution — docs + release zip.
- Сетевые read в tun-flow — deadline (правило AGENTS).
