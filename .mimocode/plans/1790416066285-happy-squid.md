# Dashboard «Обзор»: статистика из SQLite-журнала

## Goal

На главной странице «Обзор» **заменить** in-memory метрики (`GET /api/stats` / `MetricsSnapshot`) статистикой из SQLite `requests` (logs.db): агрегаты по outcome, топ хостов, график по времени, средняя/макс. длительность и байты. Период — **все записи в логе** (с учётом ретеншна). Без селектора окна.

## Design decisions

| Решение | Выбор | Почему |
|---|---|---|
| API | Новый `GET /api/logs/stats`; `/api/stats` не трогаем | smoke.sh и документы ссылаются на `/api/stats`; рядом с `/api/logs/settings` |
| Payload | Один вложенный JSON | Dashboard поллит раз в 2 с — один round-trip, консистентный снапшот |
| SQL | Один `LogCmd::Stats`, 4 запроса на writer-thread | Инвариант single-connection; ≤10k строк — дёшево |
| hit_rate | `hits/(hits+miss_like)`, `hits = HIT+HIT_REVALIDATED`, `miss_like = MISS+REVALIDATED` | REVALIDATED ≈ miss (пошёл в origin); в `MetricsSnapshot` REVALIDATED не учитывается — не «чинить» одно под другое |
| bytes_saved | `SUM(resp_bytes)` строк с HIT/HIT_REVALIDATED | соответствует `add_hit(body.len())` |
| График | **`chart.js` + `primereact/chart`** (Bar/Line) | по решению пользователя; chart.js нужно доустановить как peer dep primereact/chart |
| Бакеты | Auto-width, ~48 точек, gap-fill | ладдер `[60s,5m,15m,30m,1h,3h,6h,12h,1d]` |

## JSON schema — `GET /api/logs/stats`

Опциональные query params: `since`, `until` (unix ms). UI не передаёт → весь лог.

```jsonc
{
  "since_ms": 0, "until_ms": 0,          // MIN/MAX ts в окне
  "total": 0,
  "hits": 0, "miss_like": 0, "hit_rate": 0.0,
  "bytes_served": 0, "bytes_saved": 0, "saved_mb": 0.0,
  "avg_duration_ms": 0.0, "max_duration_ms": 0,
  "bucket_ms": 60000,
  "by_outcome": [ { "outcome": "HIT", "count": 0, "bytes": 0, "avg_duration_ms": 0.0 } ],
  "top_hosts":  [ { "host": "…", "count": 0, "bytes": 0, "hits": 0, "hit_rate": 0.0 } ],
  "series":     [ { "ts": 0, "count": 0, "hits": 0, "miss_like": 0, "bytes": 0 } ]
}
```

Пустой лог: нули, `by_outcome` = 8 каноничных строк с нулями, `top_hosts: []`, `series: []`.

Каноничный порядок outcome: `HIT, HIT_REVALIDATED, REVALIDATED, MISS, BYPASS, TUNNEL, ERROR, REJECT_CMD` (нули обязательны; неизвестные — после, sort by count desc).

## Files & steps

### 1. LogStore — `crates/rustcache-core/src/stats/logstore.rs` (+ re-export в `mod.rs`)

Типы: `LogStatsQuery`, `OutcomeStat`, `HostStat`, `SeriesPoint`, `LogStats` (serde Serialize).

`LogCmd::Stats(LogStatsQuery, Sender<Result<LogStats>>)` + `LogStore::stats()` — копия обёртки `query()` (`spawn_blocking` + mpsc).

`fn stats(conn, q)` на writer-thread, 4 SQL (WHERE через `build_filter` c `LogQuery { since_ms, until_ms, ..Default }`):

1. **totals**: `COUNT(*)`, `SUM(resp_bytes)`, `SUM/MAX(duration_ms)`, `MIN/MAX(ts)`, hit/miss-like counts, `SUM(resp_bytes)` на hits — с `COALESCE`
2. **by_outcome**: `GROUP BY outcome` → count/bytes/AVG(duration)
3. **top_hosts**: `GROUP BY host ORDER BY COUNT(*) DESC, host ASC LIMIT 10` + hits per host
4. **series**: `GROUP BY (ts / ?bucket) * ?bucket` (i64) → count/hits/miss_like/bytes

Бакеты (после Q1):
```
if total == 0 → series=[], bucket_ms=60_000
span = max_ts - min_ts
LADDER = [60s, 5m, 15m, 30m, 1h, 3h, 6h, 12h, 1d]
bucket_ms = первый шаг с span/step <= 48, иначе 1d
Rust: range floor(min/b)*b ..= floor(max/b)*b, gap-fill нулями
```

Hard rules: без `unwrap`/`expect`, `?` + anyhow; касты `as u64`/`as f64` как в `query()`.

### 2. API — `crates/rustcache/src/api/routes.rs`

- `.route("/api/logs/stats", get(log_stats))` рядом с `/api/logs/settings`
- Query extractor `{ since: Option<u64>, until: Option<u64> }`
- Handler: `st.engine.logs.stats(...)` → JSON, ошибка → `500 {"error"}` (стиль `requests()`)
- **Не** менять `/api/stats`, `/api/requests`, `pac_router`

### 3. Web client — `web/src/api/types.ts`, `web/src/api/client.ts`

- Добавить `LogStats` / `OutcomeStat` / `HostStat` / `SeriesPoint`
- Добавить `getLogStats({ since?, until? })`
- Удалить неиспользуемые `getStats()` и `Stats` (клиентская сторона)

### 4. Зависимость chart.js

```bash
npm --prefix web install chart.js
```

`primereact/chart` — обёртка над Chart.js; без `chart.js` в `package.json` сборка/runtime падают. После установки `web/package.json` dependencies должны включать `chart.js` (и `primereact` уже есть).

### 5. Dashboard — `web/src/pages/Dashboard.tsx`

Poll `getLogStats` (2 с, `alive`-guard). Разметка сверху вниз:

1. **KPI** (`stat-grid`/`stat-card`): Hit rate (accent) · Всего запросов · Попадания (HIT) · Промахи (MISS/REVALIDATED) · Средняя длительность · Макс. длительность · Сэкономлено (accent) · Отдано
2. **«Доля попаданий»** — существующий ProgressBar
3. **«Запросы по времени»** — `Chart` из `primereact/chart`, тип `bar` (стековые dataset: hits / miss_like / прочие):
   - labels — `new Date(ts).toLocaleString("ru-RU")` (или короткий формат времени в зависимости от `bucket_ms`)
   - datasets: «Попадания» (hits), «Промахи» (miss_like), «Прочее» (`count - hits - miss_like`)
   - options: `responsive`, `maintainAspectRatio: false`, legend, stacked scales; высота контейнера ~280px
   - пустой series → «Нет данных за период» вместо Chart
   - footnote: «Шаг: N с/мин/ч»
4. **Две колонки**: «Исходы» (таблица: исход · запросов · байты · ср. время, все 8) + «Топ хостов» (`DataTable`: хост · запросов · байты · hit rate)

Ошибки/пусто: текущий Card-паттерн, текст про журнал запросов.

Если файл разрастётся >~250 строк — вынести график в `web/src/components/TimelineChart.tsx`.

### 6. Styles — `web/src/styles.css`

`.chart-wrap` (height ~280px, `position: relative` для Chart), `.two-col` (1fr 1fr, media <900px → 1fr), при необходимости `.outcome-table`.

### 7. Tests

**Unit** (`logstore.rs` tests): empty; hit mapping (hits=3, miss_like=2, hit_rate, bytes_saved); zero-fill 8 outcomes; top_hosts LIMIT 10; series bucketing + gap-fill; since/until.

**Integration** (`crates/rustcache/tests/api_requests.rs`, хелперы `make_state`/`seed`/`json_get`): shape (total==3 из seed); empty DB; `?since=&until=`; hit_rate/bytes mapping.

## Risks

- Все SQL — только через writer-thread (`LogCmd::Stats`), второго `Connection` не открывать
- Литералы outcome case-sensitive (`HIT`, `HIT_REVALIDATED`, `REVALIDATED`, `MISS`, …)
- `AVG`/`SUM` → NULL → `COALESCE`; деление на 0 → `hit_rate = 0.0`
- Сначала `npm --prefix web install chart.js` — иначе `primereact/chart` не соберётся/не запустится
- Chart.js + React 19: убедиться, что `npm run build` проходит; если peer-конфликт — зафиксировать совместимую версию chart.js
- Не трогать серверный `/api/stats` (smoke.sh)
- При большом числе бакетов Chart.js сам масштабирует; max ~48 точек от ладдера
