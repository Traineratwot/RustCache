# SQLite-журнал запросов + фильтры + очистка + настройки

## Goal

Заменить in-memory `ReqRing` (100 записей) на SQLite как единственный источник правды для `/requests`. Добавить серверные фильтры/поиск/пагинацию, очистку БД, фоновую ретеншн-чистку (`max_rows` + `max_age_days`) и редактируемый блок «Логи запросов» в веб-настройках. Остальной config остаётся read-only.

## Decisions (user-confirmed)

1. Веб-настройки: **только логи** (`max_rows`, `max_age_days`, `cleanup_interval_secs`).
2. Ретеншн: **строки + возраст**, фоновая чистка по таймеру.
3. **`ReqRing` удаляется полностью** — SQLite single source of truth (переживает рестарт). `engine.record()` пишет в БД.

## Approach

### 1. Зависимость

`rusqlite` с `bundled` (вендорит SQLite, без системного libsqlite3). Не `sqlx` — тяжело и async-избыточно для одного локального файла.

```toml
# workspace Cargo.toml
rusqlite = { version = "0.32", features = ["bundled"] }  # уточнить 0.x при cargo add
# crates/rustcache-core/Cargo.toml
rusqlite.workspace = true
```

### 2. Расположение БД

Новая секция `[logs]` в config:

| Поле | Default |
|---|---|
| `db_path` | `~/.local/share/rustcache/logs.db` |
| `max_rows` | `10000` |
| `max_age_days` | `7` |
| `cleanup_interval_secs` | `300` |

Хелпер `Config::logs_db_path()` через `expand_tilde`. Файл БД **0600**, parent dir `create_dir_all`. Недоступный путь при старте — fail `run` с явной ошибкой.

### 3. Модуль: `crates/rustcache-core/src/stats/logstore.rs`

В core: `ReqRecord` уже в `stats/`, store — чистая персистентность без axum.

```
rustcache-core/src/stats/
  metrics.rs    (без изменений)
  logstore.rs   (NEW)
  mod.rs        (export logstore, убрать ring)
  ring.rs       (DELETE)
```

Типы:

```rust
// ReqRecord — без изменений, переносится из ring.rs
pub struct ReqRecord { ts, method, url, host, status, outcome, duration_ms, resp_bytes }

pub struct LogQuery {
    q: Option<String>,          // substring по url OR host
    method: Option<String>,
    outcome: Option<String>,
    status_min: Option<u16>,
    status_max: Option<u16>,
    since_ms: Option<u64>,
    until_ms: Option<u64>,
    limit: u32,                 // clamp 1..=500
    offset: u32,
}

pub struct LogPage { requests: Vec<ReqRecord>, total: u64 }
```

### 4. Schema

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 5000;

CREATE TABLE IF NOT EXISTS requests (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    ts          INTEGER NOT NULL,
    method      TEXT    NOT NULL,
    url         TEXT    NOT NULL,
    host        TEXT    NOT NULL,
    status      INTEGER NOT NULL,
    outcome     TEXT    NOT NULL,
    duration_ms INTEGER NOT NULL,
    resp_bytes  INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_requests_ts      ON requests(ts DESC);
CREATE INDEX IF NOT EXISTS idx_requests_outcome ON requests(outcome);
CREATE INDEX IF NOT EXISTS idx_requests_host    ON requests(host);
CREATE INDEX IF NOT EXISTS idx_requests_method  ON requests(method);
```

### 5. Hot path: writer thread

```
listener → engine.record(rec)          // SYNC, сигнатура не меняется
              → LogStore::enqueue(rec) // try_send, bounded channel 8192
                   → std::thread "log-writer" владеет Connection
                        → INSERT
```

- Полный канал → drop записи + rate-limited `tracing::warn!` (не блокировать прокси).
- `LogCmd`: `Insert | Query | Clear | Cleanup` + reply `std::sync::mpsc`.
- Async-обёртки `query`/`clear`/`cleanup` ждут reply внутри `tokio::task::spawn_blocking` — SQLite **никогда** не на runtime-треде, никаких `parking_lot`-локов через `.await`.
- Insert-path trim: каждые **256** вставок — только `max_rows` DELETE (счётчик в writer; `max_rows` в `AtomicU64`, обновляется cleaner'ом).

API:

```rust
impl LogStore {
    pub fn open(path) -> anyhow::Result<Self>;
    pub fn enqueue(&self, rec: ReqRecord);          // sync, non-blocking
    pub async fn query(&self, q: LogQuery) -> anyhow::Result<LogPage>;
    pub async fn clear(&self) -> anyhow::Result<u64>;
    pub async fn cleanup(&self, max_rows: u64, max_age_days: u64)
        -> anyhow::Result<(u64, u64)>;
}
```

`unwrap`/`expect` вне тестов запрещены.

### 6. API surface (`api/routes.rs`)

**`GET /api/requests`** — query params (все optional):

| Param | Meaning |
|---|---|
| `q` | substring `url` OR `host`, case-insensitive LIKE, wildcards escaped |
| `method`, `outcome` | exact match |
| `status_min`, `status_max` | inclusive |
| `since`, `until` | ms epoch, inclusive |
| `limit` | default 50, clamp 1..=500 |
| `offset` | default 0 |

SQL — только bound params. Response 200:

```json
{ "requests": [ReqRecord], "total": 1284, "limit": 50, "offset": 0 }
```

Newest-first (`ts DESC, id DESC`). Ошибка БД → 500. Кривой query → 400.

**`DELETE /api/requests`** — clear-all (не filtered) → `{ "ok": true, "deleted": N }`.

**`GET /api/logs/settings`** → `{ max_rows, max_age_days, cleanup_interval_secs }`.

**`PUT /api/logs/settings`** — body с optional-полями; валидация:
- `max_rows` ∈ 1..=10_000_000
- `max_age_days` ∈ 1..=3650
- `cleanup_interval_secs` ∈ 10..=86400

400 при нарушении. Успех: мутация `Config.logs` → write-back `config.toml` (`toml::to_string_pretty`, **тот же паттерн что exclusions**; комментарии в файле теряются — accepted) → `st.config.set` → **немедленный** `cleanup()` с новыми лимитами.

### 7. Config schema (`config/schema.rs`)

```rust
#[serde(default)]
pub logs: LogConfig,

pub struct LogConfig {
    pub db_path: String,                  // default "~/.local/share/rustcache/logs.db"
    pub max_rows: u64,                    // 10_000
    pub max_age_days: u64,                // 7
    pub cleanup_interval_secs: u64,       // 300
}
```

+ `Config::logs_db_path()`, unit-тесты defaults/parse, `config.example.toml`:

```toml
[logs]
db_path = "~/.local/share/rustcache/logs.db"
max_rows = 10000
max_age_days = 7
cleanup_interval_secs = 300
```

Hot-reload: cleaner читает `LiveConfig` на каждом тике — `live.set` достаточно. Порты/кеш-лимиты по-прежнему только с рестартом.

### 8. Engine / listeners

- `engine.rs`: `pub logs: Arc<LogStore>` вместо `ring: Arc<ReqRing>`; `record()` → `self.logs.enqueue(rec)`.
- `CacheEngine::new` принимает `logs: Arc<LogStore>`; call sites: `main.rs` (~line 115) и `tests/common/mod.rs` (~207).
- **Listeners без изменений** в call sites (`http_proxy`, `mitm_proxy`, `socks5`).
- `socks5.rs`: `outcome: "ERROR"` вместо `format!("ERROR:{e}")` (текст ошибки остаётся в tracing) — чтобы outcome-фильтр был exact-match.

### 9. Cleanup task (`main.rs`)

```sql
DELETE FROM requests WHERE ts < ?cutoff_ms;  -- now - max_age_days * 86_400_000
DELETE FROM requests WHERE id NOT IN (
    SELECT id FROM requests ORDER BY ts DESC, id DESC LIMIT ?max_rows
);
```

`tokio::spawn` loop: re-read `cfg.logs.cleanup_interval_secs` каждый wake → `sleep` → `cleanup(max_rows, max_age_days)`. PUT settings тоже дёргает cleanup сразу.

Периодический `PRAGMA wal_checkpoint(TRUNCATE)` раз в ~10 cleanup-прогонов.

### 10. Web UI

**`types.ts` / `client.ts`:** `RequestQuery`, `RequestPage`, `LogSettings`, `Config.logs`; `getRequests(query)` (URLSearchParams, без compat-shim старого лимита), `clearRequests()`, `getLogSettings()`, `updateLogSettings()`.

**`Requests.tsx`:**
- Фильтры (server-side): `InputText` q (debounce 300ms), `Dropdown` method / outcome / status-class (2xx..5xx → min/max) / time-range (1ч/24ч/7д/30д → `since`).
- Пагинация: DataTable `paginator` + `totalRecords={total}` + `rowsPerPageOptions=[20,50,100,200]`.
- Auto-refresh 2s с паузой (`ToggleButton`); ручной refresh опционально.
- Clear: `ConfirmDialog` → `clearRequests()` → toast + offset=0.
- `outcomeSeverity`: HIT/HIT_REVALIDATED→success, MISS/REVALIDATED→info, BYPASS/REJECT_CMD→warning, TUNNEL→secondary, ERROR/unknown→danger.

**`Settings.tsx`:** редактируемая карточка «Логи запросов» (`InputNumber` ×3 + Save) — паттерн Exclusions (Toast, busy). Остальное read-only.

## Implementation order

1. **Deps + schema** — rusqlite, `LogConfig`, `config.example.toml`, schema tests.
2. **`LogStore`** — logstore.rs (open/enqueue/query/clear/cleanup + unit tests), delete ring.rs, fix imports.
3. **Engine + startup** — engine.rs, main.rs (open + cleanup loop), common/mod.rs, socks5 outcome.
4. **API** — routes.rs + `tests/api_requests.rs`.
5. **Web** — client/types, Requests.tsx, Settings.tsx.
6. **Gate + smoke**.

Каждая фаза оставляет `cargo test --workspace` зелёным.

## Risks

| Risk | Mitigation |
|---|---|
| URL с секретами в query | Храним full URL (как сейчас); DB 0600. Редакция query-параметров — out of scope |
| SQLITE_BUSY | Один writer thread = единственная запись; `busy_timeout=5000` |
| rusqlite на runtime | SQLite только в writer-thread / `spawn_blocking` |
| Latency hot path | `try_send` only; drop при полном канале |
| config.toml rewrite теряет комментарии | Как exclusions — accepted |
| WAL растёт | `wal_checkpoint(TRUNCATE)` после cleanup |

UI checklist:
- `/requests`: поиск + method/outcome/status/time фильтры комбинируются; пагинация через `total`; пауза останавливает poll; Clear с подтверждением; ERROR/TUNNEL-теги с правильным severity.
- `/settings`: правка трёх полей логов → Save → toast; значения в `config.toml` `[logs]` и в `GET /api/config`; после снижения `max_rows` таблица сжимается сразу (PUT path).
- Рестарт: логи переживают (до clear).

## Out of scope

- Редактирование портов/кеш-лимитов/прочего config в UI.
- Filtered clear (только clear-all).
- Миграции/feature-flags/обратная совместимость API (поле `requests` сохраняется, добавляются `total/limit/offset`).
- Redaction query-секретов в URL (документируем residual risk).
