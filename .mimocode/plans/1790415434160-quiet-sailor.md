# Makefile для RustCache

## Цель

Создать `Makefile` в корне репозитория `/run/media/kirill/DATA2/PhpstormProjects/RustCache/Makefile` с целями:

| Target | Что делает |
|--------|------------|
| `build` | Полная сборка: фронт (`bun`) + release-бинарник с `embed-ui` |
| `start` | Запуск прокси в фоне + PID-файл |
| `stop` | Остановка по PID-файлу |
| `dev` | Backend (`cargo run`) + Vite dev параллельно |

## Решения (по ответам пользователя)

- **bun**, не npm: `bun --cwd web run …`
- **`build`** → `web/dist` + `cargo build --release --features embed-ui` (production-бинарник со встроенным UI)
- **`start`/`stop`** → фоновый процесс + `rustcache.pid` в корне
- **`dev`** → оба процесса: API на `:8080` + Vite (проксирует `/api` → `127.0.0.1:8080`)

## Файл

Новый файл: `Makefile` (корень workspace).

## Содержимое Makefile

```makefile
BIN      := target/release/rustcache
PID_FILE := rustcache.pid
CONFIG   ?= config.toml
LOG      ?= rustcache.log

.PHONY: build start stop dev

# Полная сборка: UI (bun) → web/dist, затем релизный бинарник с embed-ui
build:
	bun --cwd web install
	bun --cwd web run build
	cargo build --release --features embed-ui

# Запуск прокси в фоне (PID → rustcache.pid, лог → rustcache.log)
start: $(BIN)
	$(BIN) run --config $(CONFIG) >$(LOG) 2>&1 & echo $$! > $(PID_FILE)
	@echo "rustcache started, pid=$$(cat $(PID_FILE)), log=$(LOG)"

# Остановка по PID-файлу
stop:
	@if [ -f $(PID_FILE) ]; then \
		kill $$(cat $(PID_FILE)) && rm -f $(PID_FILE) && echo "stopped"; \
	else \
		echo "no $(PID_FILE) — not running?"; \
	fi

# Разработка: backend + Vite; Ctrl+C гасит оба
dev:
	@trap 'kill 0' EXIT INT TERM; \
	 cargo run -p rustcache -- run --config $(CONFIG) & \
	 bun --cwd web run dev

$(BIN):
	cargo build --release --features embed-ui
```

### Поведение по целям

- **`build`**: `bun --cwd web install` (идемпотентно), `bun --cwd web run build` (`tsc -b && vite build` → `web/dist`), затем `cargo build --release --features embed-ui`. Порядок важен: `embed-ui` требует `web/dist` на момент компиляции.
- **`start`**: запускает уже собранный `target/release/rustcache` (или сначала собирает, если `$(BIN)` нет). Пишет PID в `rustcache.pid`, stdout/stderr в `rustcache.log`. Не блокирует терминал.
- **`stop`**: `kill` по PID из `rustcache.pid`, удаляет pid-файл. Если файла нет — мягкий warning, не ошибка.
- **`dev`**: `cargo run -p rustcache -- run --config $(CONFIG)` в фоне + `bun --cwd web run dev` (Vite, обычно `:5173`). `trap 'kill 0' EXIT INT TERM` убивает всю группу при Ctrl+C / выходе.

### Переменные (overridable)

- `CONFIG` (default `config.toml`)
- `LOG` (default `rustcache.log`)
- `PID_FILE`, `BIN` — фиксированные, менять rarely

Пример: `make start CONFIG=config.example.toml`

## Проверка

1. `make build` — появляются `web/dist/` и `target/release/rustcache`; бинарник содержит UI (запуск + открыть `http://127.0.0.1:8080` или SPA-страницы).
2. `make start && cat rustcache.pid` — процесс жив, `curl http://127.0.0.1:8080/api/health` отвечает; `make stop` — процесс умирает, `rustcache.pid` удалён.
3. `make dev` — Vite поднимается, `/api` через Vite проксируется к `:8080` (Dashboard грузит данные). Ctrl+C убивает оба процесса.
4. Повторный `make stop` без `start` — сообщение «not running», exit 0.
