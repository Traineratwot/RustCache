# Fix 502 on every request (fake-IP DNS rejected without local TUN)

## Diagnosis

Reproduced on remote host `192.168.11.115` (Debian LXC, **no** `rustcache-tun0`):

```text
curl -x http://127.0.0.1:3128 http://example.com/  → 200
curl -x http://127.0.0.1:3128 http://yandex.ru/     → 502

getent hosts yandex.ru    → 198.18.0.29          # fake-IP
getent hosts example.com  → 8.47.69.5, 8.6.112.5 # real
```

Fake-IPs **are routable** on this network (`/dev/tcp/198.18.0.29/443` and `:80` both succeed). The LAN gateway `192.168.50.1` is a Clash/Mihomo-style fake-IP DNS; `198.18.0.0/15` answers are legitimate endpoints there.

Remote log path to 502:

1. `resolve_host: system lookup … system=["198.18.0.29:443"] real_n=0 fake_n=1`
2. `resolve_via_real_dns` — `127.0.0.53` refused, `192.168.50.1` returns **more** fake-IPs, `1.1.1.1`/`8.8.8.8` timeout or empty
3. `resolve_host: real DNS failed` → `OriginFetcher::fetch` fails → `serve.rs::error_outcome` → **HTTP 502**

Not a TUN routing loop. Remote binary is healthy (`example.com` works). This is from yesterday’s TUN-bypass work (`d48d8fe`…`e88d4bf`).

## Root cause

`resolve_host` (`crates/rustcache-core/src/net_bypass.rs:197`) **unconditionally** strips `198.18.0.0/15` from system answers (`:208-212`), and when only fakes remain falls into `resolve_via_real_dns` (`:231`). On a Clash/Mihomo network whose DNS *legitimately* returns routable fake-IPs, real DNS also returns fakes (or fails), and the error path at `:250-254` refuses to hand back the system answers → 502. Same unconditional strip in `query_dns_a` (`:473`) and `query_dns_tcp` (`:550`).

That rejection is only required when **our** capture TUN is up (`rustcache-tun0`): then those answers are poisoned by tun2proxy virtual DNS and connecting loops back into the proxy. When there is **no** local TUN, `198.18.0.0/15` may be a network-wide fake-IP DNS and **must be used as-is**. Comment at `:250-251` (“connecting to 198.18.x.x cannot work”) is false on Clash networks.

Client has the same bug: `crates/rustcache-client/src/tun/bypass.rs:94` (`feature = "tun"` compiled in ≠ interface up).

## Approach

Gate fake-IP rejection on **local TUN presence**. Pure helper so it is unit-testable. No new config keys.

| Local `rustcache-tun0` | System DNS answers | Behavior |
|---|---|---|
| absent | any (incl. 198.18.x) | use system answers as-is |
| present | has real IPs | use real IPs only |
| present | only fake-IPs | try `resolve_via_real_dns`; if that fails, error (do not connect to fake-IPs) |

## Implementation

### 1. `crates/rustcache-core/src/net_bypass.rs`

**New private helpers** (no public API change):

```rust
fn capture_tun_present() -> bool {
    std::path::Path::new("/sys/class/net/rustcache-tun0").exists()
}

/// Returns `(usable, need_real_dns_fallback)`.
fn select_system_addrs(
    system: Vec<SocketAddr>,
    tun_present: bool,
) -> (Vec<SocketAddr>, bool) {
    if !tun_present {
        let empty = system.is_empty();
        return (system, empty); // keep fakes — real endpoints on Clash networks
    }
    let real: Vec<SocketAddr> = system
        .iter()
        .copied()
        .filter(|sa| !is_capture_fake_ip(sa.ip()))
        .collect();
    let need = real.is_empty();
    (real, need)
}
```

**`resolve_host` (`:197-258`)**: replace the inline filter block (`:208-229`) with `select_system_addrs(system, capture_tun_present())`.
- no TUN → return all system answers including `198.18/15`. Real DNS **only if system was empty**.
- TUN up → keep only non-fakes; if any remain return them; else real DNS (current behavior).
- Keep `log_bypass_context`. Add `tun_present` to the `resolve_host: system lookup` info line so remote logs show which branch ran.
- Fix comment at `:250-251`: only refuse fakes while the capture TUN is up.

**`query_dns_a` (`:420-488`) / `query_dns_tcp` (`:493-553`)**: gate the fake-IP strip + “UDP hijacked → retry TCP” branch (`:470-482`, `:550`) on `capture_tun_present()`.
- no TUN: do not drop fakes, do not treat fakes as a hijack signal; keep empty→TCP retry (`:483-486`).
- TUN up: current behavior exactly.

**Docs**: module doc `:1-13` and `is_capture_fake_ip` doc `:28-29` — 198.18/15 is fake **only while our capture TUN is up**.

Leave `discover_real_dns` / `is_tun_local_addr` unchanged (minimal).

No signature changes to `resolve_host` / `connect_bypass`. Call sites (`http/fetch.rs:84`, `listeners/socks5.rs:63,179`, `listeners/mod.rs:42`) unchanged.

### 2. `crates/rustcache-client/src/tun/bypass.rs` (same fix)

`tun::bypass` is used by `proxy::relay` whenever the `tun` feature is on, even if `rustcache-tun0` is down.

- Add `capture_tun_present()` + `select_system_addrs()` with the same semantics (keep `std::io::Error` API).
- `resolve_host` (`:94-126`): replace unconditional filter (`:105-112`) with the selector; fall back to `query_real_dns` only when `need_real_dns`.
- `query_real_dns` (`:129-192`): today does **not** strip fakes (inconsistent with core). Gate a `is_capture_fake_ip` strip on `capture_tun_present()` — closes a latent TUN-loop hole; when no TUN leave answers intact.
- Doc fix `:91-93`. `is_capture_fake_ip` stays as-is.

No changes in `proxy/relay.rs`.

### 3. Regression tests (name after the failure mode)

In `net_bypass.rs` `mod tests` (pure, no network):

- `system_fake_ip_is_usable_when_no_capture_tun` — `select_system_addrs([198.18.0.29:443], false)` keeps the addr, `need_real_dns == false`
- `system_fake_ip_is_dropped_when_capture_tun_present` — same input, `true` → empty usable, `need_real_dns == true`
- `real_system_answers_preferred_even_with_capture_tun` — mixed list, TUN up → only real ones
- `real_dns_fallback_only_when_system_empty_or_only_poisoned` — empty→fallback; real→no; fake-only+TUN→fallback

Existing `fake_ip_detection` stays (range check unchanged).

Client mirror tests in `tun/bypass.rs` for the same two TUN on/off cases.
