> Память о проекте между сессиями. Технический справочник (стек, раскладка

> история значимых правок.

## Что за проект

Кеширующий HTTP/HTTPS прокси на Rust: MITM для HTTPS, диск + память под кеш,
SOCKS5-туннель, локальный REST API и веб-интерфейс (React) для управления.
Репозиторий: `~/web/technolight/RustCache`, ветка по умолчанию `main`,
CI — GitHub Actions (`.github/workflows/ci.yml`, quality + web build).

## Окружение разработки

**На этом Mac нет тулчейна Rust** (`cargo` не установлен). Сборка и проверки
идут в Docker:

```bash
docker build -t rustcache-dev:1.90 - <<'EOF'
FROM rust:1.90
RUN rustup component add rustfmt clippy
EOF

docker run --rm -v "$PWD":/work -w /work \
  -v rustcache-cargo-reg:/usr/local/cargo/registry \
  -v rustcache-target:/target -e CARGO_TARGET_DIR=/target \
  rustcache-dev:1.90 cargo test --workspace
```

Локальный `bun` (1.3.x) старше формата `web/bun.lock`. Веб-проверки — тоже
в контейнере: `docker run --rm -v "$PWD":/work -w /work oven/bun:1 \
bash -c 'bun install --cwd web --frozen-lockfile && bun run --cwd web lint && bun run --cwd web build'`.

## История изменений

### 2026-09-29 — аудит: баги, безопасность, архитектура (`fix/audit-2026-09`)

Полный обзор кодовой базы. Разбито по причинам, а не по файлам.

**Безопасность**

- *Коалесинг сливал ответы между пользователями.* Ключ single-flight для
  запросов с `Authorization` был `{key}:auth:{кол-во заголовков}` — два разных
  пользователя с одинаковым числом заголовков на один URL получали один ответ
  от origin. Аутентифицированные запросы теперь не коалесятся вовсе
  (`engine.rs`).
- *Админский API был доступен для CSRF и DNS-rebinding.* Привязка к 127.0.0.1
  не спасает: `POST /api/config/restart` идёт без тела и без preflight, то есть
  любая открытая пользователем страница могла перезапустить прокси. Добавлен
  `api::guard::local_origin_guard` — проверка `Origin` и `Host`
  (`tests/api_guard.rs`). PAC-листенер намеренно оставлен открытым.
- *В журнал запросов писались секреты из query string.* `LogStore::enqueue`
  прогоняет URL через `stats::redact_url`.
- *WAL-файлы `logs.db-wal` / `-shm` оставались с правами по умолчанию,* хотя
  содержат те же данные. `set_db_mode` теперь ставит 0600 и на них, и
  вызывается после включения WAL.

**Корректность**

- *После `304` запись оставалась просроченной* → каждый следующий запрос снова
  шёл на origin. Свежесть пересчитывается по заголовкам самого 304, а при
  отсутствии в нём `Date` окно `max-age` отсчитывается от момента получения.
- *`Cache-Control: max-age=…, immutable` полностью терял max-age* (ветка
  `if !p.immutable` пропускала присваивание) — запись оставалась без срока
  годности. Самая частая форма immutable в реальном вебе.
- *Отменённый лидер single-flight навсегда занимал ключ:* при обрыве клиента
  `Sender` оставался в карте, и все последующие запросы к этому URL висели.
  Добавлен `InflightGuard`, снимающий слот в `Drop`.
- *Денилист MITM был вечным* — одна разовая ошибка TLS отключала MITM (и кеш)
  для хоста до перезапуска. Теперь TTL 5 минут.
- *Листовые сертификаты не принимались клиентами Apple* (по умолчанию rcgen
  даёт срок до 4096 года, лимит Apple — 398 дней) и ломались для
  IP-адресов (SAN перезаписывался на `DnsName`). Исправлено оба.
- *`wait_for_restart_parent` проверял `/proc/{pid}`* — на macOS/BSD такого пути
  нет, ожидание всегда завершалось мгновенно и перезапуск гонялся за портами.
  Теперь `kill(pid, 0)`.
- *Запись `config.toml` не была атомарной* и гонялась с notify-вотчером.
  Теперь tmp + rename.
- *Порядок записи в дисковый кеш* — сначала тело, потом индекс (иначе краш
  оставлял метаданные без тела). `touch` берёт write-lock, иначе он
  воскрешал индекс удалённой записи.
- *Исключения не срабатывали для IPv6-литералов* (`https://[fd00::1]/`) —
  скобки не снимались, адрес не парсился. Заодно отбрасывается userinfo.
- *`useApi().reload()` в вебе ничего не делал* — эффект имел пустые зависимости,
  а `deps` игнорировались. Хук нигде не использовался, но был ловушкой.

**Устойчивость**

- Ни у одного сетевого чтения не было дедлайна: клиент, открывший сокет и
  молчащий, держал таск вечно. Добавлены `listeners::HANDSHAKE_TIMEOUT` (30 с)
  и `CONNECT_TIMEOUT` (15 с), а также `OriginFetcher::read_timeout` (60 с).
  Туннели (`copy_bidirectional`) намеренно остались без ограничения.
- Hop-by-hop заголовки больше не пересылаются на origin; `Connection: close`
  ставится всегда.
- `rustls::ServerConfig` кешируется по хосту (`MitmState::tls_configs`) — раньше
  он строился на каждый CONNECT, то есть на каждый HTTPS-запрос.

**Гигиена**

- `cargo clippy --workspace -- -D warnings` был **красным** на текущем stable
  (CI использует `dtolnay/rust-toolchain@stable`). Починено; гейт в `AGENTS.md`
  переведён на `--all-targets`, иначе интеграционные тесты не линтуются вовсе.
- Новые зависимости: `time` (срок действия сертификатов), `libc`
  (`kill(pid, 0)`), `x509-parser` (dev-only, разбор сертификатов в тестах).

## Не сделано (осознанно)

- **Keep-alive не поддержан**: каждое соединение обслуживает один запрос. Для
  MITM это означает CONNECT + TLS-рукопожатие на каждый запрос браузера —
  самая крупная оставшаяся статья расходов. Помечено как вне рамок в
  `http_proxy.rs`.
- **Прокси-листенеры жёстко привязаны к `0.0.0.0`**: в конфиге есть только
  `port`, без `bind`. Для LAN-прокси это задумано, но настройки адреса нет.
- **`Vary` не входит в ключ кеша** (известное ограничение, уже в `AGENTS.md`).
- **Тяжёлые аналитические запросы идут через тот же writer-поток**, что и
  вставки в журнал: долгий `/api/logs/stats` может переполнить канал и привести
  к потере записей.
